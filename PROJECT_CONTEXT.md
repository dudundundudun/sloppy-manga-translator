# Контекст проекта: Local Manga / Manhwa / Manhua Translator (v1.0.5)

Этот документ содержит полное техническое описание, историю разработки, особенности окружения и структуру всех файлов локального переводчика манги/манхвы/маньхуа. Скопируйте или прикрепите этот файл (вместе с архивом `sloppy-manga-translator-main.zip`) в начале нового чата, чтобы продолжить разработку без потери контекста.

* **ОС:** Windows 11
* **Рабочая папка проекта:** `C:\Users\Alexey\Documents\manga-translator-git\sloppy-manga-translator`
* **Папка расширения Chrome:** `C:\Users\Alexey\Documents\manga-translator-git\sloppy-manga-translator\extension`
* **Видеокарта:** NVIDIA GeForce RTX 5070 Ti (16 ГБ VRAM, архитектура Blackwell)
* **Python:** Python 3.14 (`C:\Users\Alexey\AppData\Roaming\Python\Python314`)
* **Ключевые установленные версии пакетов:**
  * `torch 2.10.0+cu130` (CUDA 13.0)
  * `numpy 2.4.4`
  * `opencv-python 5.0.0.93`
  * `ultralytics` (YOLOv8), `manga-ocr`, `fastapi`, `uvicorn`, `httpx`, `pillow`
* **ВАЖНОЕ ОГРАНИЧЕНИЕ ПО УСТАНОВКЕ ПАКЕТОВ (`pip`):**
  На Python 3.14 нельзя запускать обычную установку пакетов со старыми закрепленными зависимостями (таких как `simple-lama-inpainting` или `easyocr`) без флага `--no-deps`, иначе `pip` попытается понизить версию `numpy` и собрать старый `numpy` из исходников (или перезаписать `opencv-python` на `opencv-python-headless` с ошибкой `WinError 5: Отказано в доступе` на `cv2.pyd`).
  * Поэтому дополнительные пакеты ставятся строго через `--no-deps` (см. `install_multilang_ocr.bat`).
* **ВАЖНОЕ ОГРАНИЧЕНИЕ ПО `.bat` ФАЙЛАМ В WINDOWS:**
  Все `.bat`-файлы (`start_gui.bat`, `start_server.bat`, `register_chrome_launcher.bat`, `install_multilang_ocr.bat`, `translate_folder.bat`, `test_page.bat`) должны содержать **только ASCII (английские символы)** и окончания строк `CRLF (\r\n)`.
* **Локальные и облачные LLM-серверы пользователя:**
  1. **ModuleAPI / DeepSeek API** (`https://moduleapi.pro/v1`) — облачные модели `deepseek-v4-flash` и `deepseek-v4-pro`.
  2. **Ollama** (`http://127.0.0.1:11434`) — локальные модели (`shisa-v2.1`, `gemma3:12b`, `qwen2.5:14b`, `qwen3.5`).
* **Особенность сети (VPN / Системный прокси):**
  Во всех клиентах `httpx` используется `trust_env=False` и переменные окружения `NO_PROXY="127.0.0.1,localhost"`.

## 2. Схема расположения файлов по папкам (v1.0.5)

```text
sloppy-manga-translator/
├── PROJECT_CONTEXT.md             # Полное описание проекта и контекст (v1.0.5)
├── gui_app.py                     # Десктопное графическое приложение (Tkinter + Pillow)
├── start_gui.bat                  # Быстрый запуск Веб-Студии и сервера (чистый ASCII + CRLF)
├── start_tk_gui.bat               # Быстрый запуск десктопного Tkinter GUI (чистый ASCII + CRLF)
├── web_studio.html                # Локальная Веб-Студия (доступна на http://127.0.0.1:5000/)
├── ocr_engine.py                  # Детекция бабблов (YOLOv8) + пакетный MangaOCR FP16 + фильтр вздохов/SFX
├── translator.py                  # Параллельный перевод на EN, RU и Ромадзи через Ollama / Cloud API
├── cleaner.py                     # Удаление текста из бабблов и свободных надписей на фоне (SimpleLama / TELEA)
├── renderer.py                    # Овальная и прямоугольная верстка с выбором мин./макс. шрифта
├── server.py                      # FastAPI сервер (порт 5000, авто-перезапуск старых версий, пакетный конвейер)
├── cli_client.py                  # Консольный клиент для test_page.bat и translate_folder.bat
├── start_server.bat               # Ручной запуск локального сервера (чистый ASCII + CRLF)
├── install_multilang_ocr.bat      # Безопасная установка EasyOCR (--no-deps) для KO/ZH и CRAFT-детектора
├── install_shisa_models.bat       # Автоустановка локальных моделей Shisa V2.1 в Ollama
├── register_chrome_launcher.bat   # Регистрация протокола manga-translator:// в реестре Windows
├── translate_folder.bat           # Пакетный перевод папки с продолжением с места остановки
├── test_page.bat                  # Быстрый тест перевода одной страницы
└── extension/                     # Папка расширения для Chrome (Manifest V3)
    ├── manifest.json
    ├── background.js
    └── content.js
```

## 3. История ключевых обновлений (v0.9.9 ➔ v1.0.5)

### Версии v0.9.9 – v1.0.1:
1. **Локальная Веб-Студия (`web_studio.html`) и десктопный GUI (`gui_app.py`)**:
   * Интерактивные рамки `#N` на странице манги: перетаскивание мышкой, растягивание/сжатие за 8 маркеров (`nw..w`), изменение размера шрифта колесиком мыши, компактный попап редактирования рядом с кружком по клику.
   * Независимые координаты `clean_bbox` (место замазки оригинального текста остается на месте) и `bbox` (новое место и размер рамки перевода).
   * Полное удаление любых рамок кнопкой `🗑` (с восстановлением чистого оригинального рисунка и отменой `Ctrl+Z`), значок сохранения `💾` прямо на рамке, настраиваемый интервал автосохранения рамок (`0.5–30 сек`, отключен при вводе текста с клавиатуры).
   * Фильтр объема переводимого текста (`dialogue_only`, `bubbles_no_sighs`, `long_only`, `bubbles_only`, `all`) с автоматическим пропуском коротких вздохов («а», «о», «ах», «ох», «мм») и звуковых спецэффектов (SFX).

### Версия v1.0.2 (Оптимизация расхода токенов DeepSeek API и защита от шторма запросов):
1. **Устранение поштучного шторма запросов при отказе цензуры (`_translate_batch_chunk` в `translator.py`)**:
   * Полностью удален цикл поштучного доперевода каждого кружка, который при отказе облачного фильтра безопасности (`I can’t translate or intensify explicit sexual content...`) отправлял до 85 отдельных запросов подряд.
   * Добавлен детектор отказов цензуры `_is_refusal_response` и санитизатор слов-триггеров родства/возраста `_sanitize_safety_triggers_for_cloud`.
2. **Запрет скрытого переключения `deepseek-v4-flash` ➔ `deepseek-v4-pro`**:
   * Из `_call_llm_json` убран авто-перебор моделей и удален вызов `self.save_config(selected_model=...)` во время перевода.

### Версия v1.0.3 (Ускорение пакетной обработки 12 страниц в 3–4 раза и авто-перезапуск старого сервера):
1. **Автоматический перезапуск старого фонового процесса сервера (`server.py`, `gui_app.py`)**:
   * Версия API сервера в `/health` обновлена до `"1.0.3"`. При запуске `start_gui.bat`, `server.py` или `gui_app.py` проверка `_is_server_already_running()` обнаруживает старый процесс `v1.0.0` (например, оставшийся в памяти в фоне), автоматически отправляет ему `POST /shutdown` и запускает обновленный сервер `v1.0.3`.
2. **Приоритетная проверка японского языка без ложного скачивания EasyOCR (`ocr_engine.py`)**:
   * В `detect_page_language()` оценка японского языка через уже загруженный в VRAM `MangaOCR` (`_evaluate_ja()`) всегда выполняется **первой** (независимо от соотношения вертикальных и горизонтальных рамок на странице). Если на странице обнаружена японская кана (`kana_chars >= 2`), мгновенно возвращается `"ja"` без инициализации и скачивания тяжелых моделей `EasyOCR` (`ko` / `ch_sim`).
3. **Авто-нейтрализация слов родства при ложных отказах облачного фильтра (`_sanitize_safety_triggers_for_cloud` в `translator.py`)**:
   * Если облачный шлюз `moduleapi.pro` блокирует пачку с ошибкой `"I can’t translate explicit sexual content involving a parent and child / incest"`, перед повторной отправкой подгрупп японские слова родства (`お父さん`, `父さん`, `パパ`, `娘`, `実の娘`, `お兄ちゃん`, `妹`, `子供` и др.) автоматически заменяются на нейтральные местоимения (`あなた`, `ダーリン`, `彼女`, `女の子`, `先輩`), благодаря чему перевод проходит с первого же ретрая.
4. **Параллельный облачный перевод (`CLOUD_PARALLEL_CHUNK_SIZE = 42`, `asyncio.gather`) и батчинг `MangaOCR` в FP16**:
   * Большие пачки (>42 фраз с 12 страниц) делятся на 2–3 параллельных потока и переводятся одновременно за 14–18 секунд вместо 50–55 секунд.
   * Распознавание всех бабблов страницы в `MangaOCR` выполняется одним пакетным GPU-вызовом в FP16, а очистка и рендеринг страниц пачки идут параллельно в 4 потока.

### Версия v1.0.5 (Встроенная система диагностики, профилирования этапов и авто-логирования):
1. **Автоматическое сохранение логов на диск (`logs/`)**:
   * Все события сервера, предупреждения и ошибки автоматически записываются в ротируемый UTF-8 файл `logs/miko_studio.log` (до 5 МБ × 3 копии), а также в кольцевой буфер в ОЗУ (`RingBufferLogHandler` на 400 записей + отдельный буфер `WARNING`/`ERROR`).
   * Все замеры производительности сохраняются в структурированный журнал `logs/diagnostics_events.jsonl`.
2. **Пошаговый профайлер скорости (`OCR` vs `ИИ` vs `Очистка+Верстка`) и телеметрия API (`server.py`, `translator.py`)**:
   * Для каждой переведенной страницы и каждой пачки (12 страниц) замеряется точное время каждого этапа в секундах и процентах (`ocr_sec`, `llm_sec`, `render_sec`, `total_sec`, `sec_per_page`, `vram_mb`) и выводится сводной строкой `📊 [ДИАГНОСТИКА ПАЧКИ #N]`.
   * В `OllamaTranslator` ведется статистика сессии (`diagnostics_stats` и `recent_api_calls`): число запросов к Cloud API и Ollama, число параллельных пачек, процент попаданий в кэш (`cache_hit_rate_pct`), среднее время ответа ИИ, число отказов цензуры (`refusals_count`), срабатываний санитизатора слов родства (`sanitized_retries_count`) и микро-допереводов (`micro_retries_count`).
3. **Эндпоинты и интерфейс «🩺 Диагностика и Логи» в Веб-Студии и Tkinter GUI**:
   * Добавлены эндпоинты `GET /diagnostics`, `GET /diagnostics/report`, `GET /diagnostics/download_log`, `POST /diagnostics/open_logs`, `POST /diagnostics/clear`.
   * В верхнюю панель `web_studio.html` и `gui_app.py` добавлена кнопка **«🩺 Диагностика»** с кнопкой **«📋 Скопировать отчет для чата (в 1 клик)»**, которая формирует полный диагностический отчет (с маскировкой API-ключа) для мгновенной вставки в чат (`Ctrl+V`).
